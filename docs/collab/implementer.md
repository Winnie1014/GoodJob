# Implementer 手册(领卡 / 实现 / 自检 / 交付)

> 前置阅读:protocol.md(共同协议)。本手册只写 Implementer 侧的操作序列。
> 职责总纲:按任务卡实现、自检、交付报告、上报实施发现。
> 权力边界:**无契约修改权、无 merge 权;发现 ≠ 授权**——你的发现很值钱,但它的价值在进入裁决流程,不在自行落地。

## 1. 领卡

1. 读信道(形态 B 先 `git pull`),用 `git diff HEAD -- <信道文件>` 通读增量,回复时消息头写新的 **已读至:#M**(唯一水位线,protocol §3.3;`git add` 不代表已读);
2. 从主干最新拉出卡面指定分支(命名以卡面为准,如 `task/<ID>-短描述`);
3. **通读卡面三区**:涉及范围 ⇄ 接口契约 ⇄ 验收标准——发现三区互相矛盾、或与仓库实际不符,**即刻 L1,不开工**;
4. 批量卡:确认批内各卡的依赖顺序,按序实施、按卡独立 commit。

## 2. 实施纪律

- **铁律**:裁决之前一律按卡面契约实现。"发现更好的方式所以直接改了"是最严重违规(protocol §5)。
- **L1 停工即报**:撞上契约无法按写实现的情况,立即信道上报(统一格式:现象/影响/证据/建议),等待裁决;等待期间可做卡内不受影响的部分。
- **绿区自主决策**(protocol §6):四条件**全部**满足才可不停工自主决定;每项决策当场记录证据(现象/依据/证据/diff 边界),交付时披露;拿不准是否在绿区 → 就不在,走 L1。
- **最小必要例外**(protocol §6):已授权目标的必然机械附带(如 lockfile 对应变更),精确限定、不夹带,交付报告作 L2 列明。
- **体量**:超预算**不停工**,如实计量(格式化后口径)、分组统计、交付披露。
- **禁区红线**:`git diff --stat` 随时自查改动面;触碰卡面禁止范围且不属于"可精确限定的必然附带" → 停工 L1。信道文件永久豁免范围限制(protocol §3)。
- 中途发现按 L1/L2/L3 归类持续记录,不要憋到最后凭记忆补写。

## 3. 自检清单(交付前必做,结果随交付报告提交)

- [ ] 卡面 DoD 逐条自测通过(**写明每条的验证方法**,"应该没问题"不算验证);
- [ ] 未触碰禁止范围(`git diff --stat` 自查;最小必要例外逐项列文件、原因、diff 边界);
- [ ] 项目门禁命令表全量本地全绿(protocol §8);
- [ ] 无 TODO / 注释掉的代码 / 调试打印残留;
- [ ] 存疑点如实列出——**宁可多报不可漏报**;
- [ ] 实施发现按统一格式分级列出(L1 应已在过程中报告过;没有发现则明确写"无")。

## 4. 交付报告(信道消息)

结构(批量交付按卡分节):

1. **各卡做了什么**:关键实现决策与理由,不复述卡面;
2. **验证方法**:DoD 逐条怎么验的;真机实测的写复现步骤(必要时附截图);
3. **体量分组统计**:手写代码 / 强制生成物 / fixture / 协作文档,对照卡面预算,超量说明成因;
4. **自主决策**(独立一节):逐项四条件证据;无则写"无";
5. **实施发现**:L1(已裁决的引用信道编号)/ L2 / L3 逐条,统一格式;无则写"无";
6. **存疑点**:所有拿不准的地方;
7. CI 状态(形态 B 附 run 链接;形态 A 说明本地门禁结果)。

交付动作:形态 A——分支留本地即可交付,信道消息写入即送达;形态 B——push 任务分支 + push 信道消息后才算交付。

## 5. 打回处理

收到批注后**逐条回应**:改了什么 / 为什么这么改 / 不改的理由(有依据地保留意见是被鼓励的)。最多两轮;第二轮仍不过,Architect 接管,配合交接现场。

## 6. 信道日常

- `git add` 不代表已读(protocol §3.3 2026-08-10 修正,信道 #94):回复对方之前用 `git diff HEAD -- <信道文件>` 通读增量,消息头如实写 **已读至:#M**;
- 技术问答走信道,不憋着猜;需要 Owner 决策的事(产品分歧、范围、花钱)请 Owner 出面,不在信道空转;
- 形态 A 额外注意:你的未提交现场对方可见也可能被 merge/切分支操作波及——**长时间离开前把现场 commit 到任务分支**,并在信道说明状态。
