## 背景（为什么做）

契约指针：[验收基线 §1](../../40-delivery/acceptance-baseline.md)、[ADR-0008](../../30-decisions/adrs/ADR-0008-single-file-dashboard-and-structured-token-embedding.md) 决策 8。

门禁目前是**六条要人手敲的命令**，分散在两个目录，只写在 README 里。仓库根没有 `Makefile`、没有 `justfile`、没有 CI 配置。

这不只是"敲起来麻烦"。`dashboard.js` / `dashboard.css` 是从 `frontend/src/*.ts` 构建出来、**提交进仓库**的产物，Python 侧运行时直接读它们。我在 2026-07-31 做了实测：改 `frontend/src/dashboard.ts` 里一句 UI 文案、**不重新构建**，然后跑全套门禁——

```text
uv run pytest -q（180 个用例）      -> 绿
npm run verify（跨引擎行为门禁）    -> 绿
npm run build:check                -> 红
```

`npm run verify` 也是绿的，因为它调用 Python 的 `render_dashboard_html`，而后者读的同样是**已提交的产物**，不感知 TypeScript 源码。

也就是说：**全套门禁里只有 `build:check` 这一条知道源码与产物是否还对得上，而它挂在需要浏览器准备步骤的那条链子上。**漏敲一次 `npm test`，源码与产物就能静默分叉，而且分叉之后所有其他门禁继续全绿。

## 目标（做成什么样）

仓库根一条命令跑完日常门禁，退出码即结论，任何一条子门禁失败都能一眼看出是哪条；构建漂移落在这条命令的覆盖范围之内。

## 涉及范围

- **允许**：仓库根新增 `Makefile`；`README.md` 的「本地开发」段
- **禁止**：其余一切文件。特别是 `runtime/` 下的任何源码与测试、`package.json` 的 scripts、`pyproject.toml`、`docs/` 下的契约文档
- **零新增依赖**：不装 `just` / `task` / `nox` / `tox` / `pre-commit` / `make` 的任何替代品。本机 GNU Make 3.81 已就位，用它

## 接口契约

Architect 给定，不得擅改：

1. 入口是仓库根的 `Makefile`。**不用 shell 脚本**：Make 的目标依赖关系是声明式的，且自带 `-n` 干跑，Owner 能在执行前看清将要跑什么。
2. 目标至少四个，命名固定：
   - `make gate`——**日常门禁**：Python 四条（`ruff format --check`、`ruff check`、`mypy`、`pytest -q`）+ 前端 `npm test`。**不含** `npm run verify`。
   - `make gate-python`、`make gate-frontend`——上面两半各自可单独调用。
   - `make gate-release`——`gate` 之上再加 `npm run verify` 与 `uv build`。
3. **`make gate` 必须覆盖构建漂移**。`npm test` 已包含 `build:check`，所以只要 `gate` 包含 `npm test` 即成立——但必须由 DoD 的漂移自检证明，不能只靠推理。
4. 任一子命令失败时，`make` 以**非零退出**，且输出能定位到是哪一条子门禁失败。**不得**用 `-` 前缀忽略错误、不得 `|| true`、不得把多条命令用 `;` 串成一条掩盖中间失败。
5. **不改任何门禁命令本身**：不放宽参数、不删条目、不调换 `npm test` 内部的既有顺序。本卡只做聚合，不做取舍。
6. `npm run verify` 保持在日常门禁之外（[GJ-04](GJ-04.md) 契约 8 已裁决：浏览器二进制属本机发布前依赖）。**不得**把它并进 `make gate`。
7. `README.md` 的「本地开发」段改为以 `make` 为主入口，**同时保留**展开后的原始命令清单——Owner 常常只想跑其中一条，聚合不应该把单条命令藏起来。

## 实现指引

- 两个门禁目录不同（`runtime/` 与 `runtime/frontend/`），用 `$(MAKE) -C` 或在配方里 `cd`，两种都可以，选一种写清楚。
- Make 的每一行配方是独立 shell，`cd` 不跨行保留——这是最容易踩的坑。
- 目标都不产出文件，记得声明 `.PHONY`。
- `npx playwright install webkit chromium` 是一次性准备步骤，不要放进任何 `gate*` 目标里——那会让门禁在网络不通时失败。README 里保留它作为前置说明即可。

## 验收标准（DoD）

## 边界与禁区

- 不引入 `just` / `task` / `nox` / `tox` / `pre-commit` 或任何门禁运行器——红区，一律 L1。
- **不加 CI 配置**（GitHub Actions 等）。是否上 CI 是独立决策，不在本卡，想提按 L3。
- 不把 `npm run verify` 并入 `make gate`（契约 6）。
- 不改任何门禁命令的内容或参数（契约 5）。发现某条门禁本身有问题 → L3，裁决前不得改。
- 不改 `runtime/` 下任何文件。
- 卡面与实际代码矛盾时停工 L1。
