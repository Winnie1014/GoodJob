### 一、数据区转义目前没有运行期守卫

GJ-01 把结构门禁的判定范围收窄到产物结构后，数据区不再被任何**运行期**规则检查。验收时我做了变异测试：撤掉「范围收窄」但保留 `=` 转义，`test_reporting.py` 22 个用例**全绿**。穷举探测确认了原因——`=` 与 `<` 都被转义后，结构正则在数据区永远不可能命中，两层是纯冗余，第二层无法被任何输入驱动的测试区分。

这不是坏事，但意味着**转义本身的正确性只由测试夹具保证，没有运行期不变量**。若 `_embedded_json` 的某个 `replace` 将来被删掉，产物会带着可断开 `</script>` 的裸字节发布，只有恰好覆盖到的测试会红。

正确形态是两个**各自可测**的层：结构门禁只判产物结构；数据区由自己的规则判「必须已完全转义」。

### 二、归因散文投影在接缝处漏检

`_personal_attribution_prose` 剔除非散文 token 后**无分隔符**直接拼接，被剔除处不留词边界：

```text
['结果', code'X', 'I led this']  ->  '结果I led this'  ->  \bI\b 不命中
```

这**不是批次 A 引入的回归**（改动前的全串拼接在同样输入下同样不命中），但插入分隔符会严格更保守。

## 目标（做成什么样）

## 接口契约

Architect 给定，不得擅改：

1. `render_dashboard_html` 在拼装产物前，对 `_embedded_json` 的输出增加**渲染期后置断言**：数据区不得含裸 `<`、`>`、`=`、`&`、U+2028、U+2029 及现有可见控制符集合。违反抛 `InvalidInputError`，`code` 不变。
2. 该断言是**独立于结构门禁的一层**：结构门禁只看产物结构，数据断言只看数据区。**不得把两者合并回一次全文匹配**——那正是 `D-043` 禁止的形态。
3. 断言的字符集合与 `_embedded_json` 的转义集合必须来自**同一处定义**，不得各写一份常量。转义集合将来增删时，断言自动跟随。
4. `_personal_attribution_prose` 在参与投影的 token 之间插入换行符分隔，使被剔除的 token 在投影中留下词边界。
5. 分隔符**只作用于散文投影**；`_resolve_tokens` 返回的完整 statement 拼接保持无分隔符，契约不变。
6. 契约 4 会让检出更宽（例如「单位矩阵 I」这类非第一人称的 `I` 更容易被判为个人归因）。**这是刻意选择的方向**：检出偏严只会要求补个人上下文，漏检则会让个人归因绕过校验。不得为压制这类误报去收窄 `_FIRST_PERSON_PATTERN`。

## 实现指引

- 契约 3 的做法之一：把转义映射抽成模块级常量（字符 → 转义序列），`_embedded_json` 用它做替换，断言用它的键做检查。注意 `&` 必须先替换的既有顺序不能破坏。
- 契约 1 的断言是 O(n) 单次扫描，发生在冻结之后、拼装之前；不要放进 `_validate_dashboard_document`（那是结构层）。
- 契约 4 的分隔符选换行符而不是空格：换行符不会出现在正常 token 值里参与构词，且对既有中文语料不产生额外语义。
