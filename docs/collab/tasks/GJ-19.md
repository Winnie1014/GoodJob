## 背景

信道 [#73 七](../channel.md) 记录：GJ-16B 运行中 `apps/mobile/ios/Flutter/ephemeral/flutter_native_integration.env` 通过了 `WorkspaceScanner._is_sensitive`，进入 `source_artifacts` 与 `source_revisions` 并产生 1 条 Evidence。该文件为 Flutter 生成的构建配置，无凭据，且经核未进入任一 HTML 产物，**不构成泄漏事故**——但闸门本身有覆盖缺口。

**出卡侧更正（本卡为准，覆盖 #71 第四条与 #73 第七条的表述）**：`_is_sensitive` 的判定**已有四种形态**——精确名（`== ".env"`）、前缀（`.startswith(".env.")`）、固定名字集合（`in {...}`）、后缀（`.endswith((".key", ".p12", ".pem", ".pfx"))`）。因此缺陷**不是"缺少后缀机制"**，而是 `.env` 未纳入后缀集合，导致 `production.env`、`local.env`、`secrets.env` 等常见命名漏判。#71/#73 称"判的是名等于或前缀，不是后缀"，遗漏了既有后缀分支，特此更正——**这处更正本身就是"未验证断言当事实"的实例**，也是本卡送预审的直接理由。

## 目标

敏感文件判定的覆盖面由**枚举**决定，而不是由历史上碰巧遇到过的文件名决定；每个判定形态的成员集合有明确来源。

## 涉及范围

- **允许修改**：`runtime/src/goodjob/scanner.py` 中 `WorkspaceScanner._is_sensitive`；`runtime/tests/test_scanner.py` 新增用例。
- **禁止**：修改 `IgnoreMatcher`（属 GJ-18）、`_classify`、遍历结构、schema、前端、依赖、权威契约、`SKILL.md`、`scripts/session.py` 授权序列；禁止读取或修改 CodeRoute、SliverShield 及 `~/.codex/goodjob-career-review/acceptance/`；**禁止按文件内容嗅探**——本卡只处理按名判定，内容嗅探是独立设计问题，如认为必要按 L3 建议。

## 接口契约

**契约 1 — 四个形态各自的成员集合要有来源。** 对精确名 / 前缀 / 名字集合 / 后缀四类，分别说明成员从何而来（生态惯例、工具官方文档、既有集合沿用）。**不接受"凭经验补几个"**——每个新增成员在交付报告里给出处。

**契约 2 — `.env` 必须由后缀形态覆盖。** `production.env`、`local.env`、`secrets.env` 判为敏感。同时保持 `.env` 自身与 `.env.production` 形态仍判为敏感（注意：`".env".endswith(".env")` 为真，合并时勿删出既有覆盖的洞）。

**契约 3 — 判定为敏感必须可见。** 当前 `_is_sensitive` 命中后只做 `excluded["sensitive"] += 1`，用户无从知道哪个文件被排除。本卡需使排除结果可被使用者观察到——**具体形式（ScanIssue / Coverage 说明 / 计数分类）由 Implementer 提案，在交付报告说明选择理由**；不得泄漏被排除文件的内容，路径披露粒度按现有 `_short` 口径。

**契约 4 — 假阴性优先于假阳性。** 拿不准的名字**判为敏感**。漏判的后果是凭据进证据链，误判的后果是少一份证据素材——两者不对称。

**契约 5 — 无新增运行时依赖。** 同 GJ-18 契约 5。

## DoD

**D1｜后缀覆盖。** `_is_sensitive("production.env")`、`("local.env")`、`("secrets.env")` 均为 `True`，各有独立用例。

**D2｜既有覆盖零回归。** 修改前 `_is_sensitive` 判为 `True` 的每一个名字，修改后仍为 `True`。**以参数化用例覆盖当前实现的全部成员**，不抽样。

**D3｜变异断言（防假绿）。** 从后缀集合移除 `.env` 后，D1 用例必须变红。交付报告贴出变异前后失败用例名集合。

**D4｜阴性对照。** `.envoy`、`environment.md`、`env.example`、`README.env.md` 等**形近但不应判敏感**的名字为 `False`——防止把后缀写成子串匹配。若认为其中某个应判为敏感，按 L2 上报并说明，不擅自改判据。

**D5｜排除可见。** 构造含敏感文件的合成工作区，扫描后能从产出中观察到"有文件因敏感被排除"，且**产出中不含该文件内容**。断言方式随契约 3 的选型确定。

**D6｜来源表。** 交付报告含四形态成员来源表，每个本卡新增成员一行。

**D7｜门禁全绿。** [protocol §8](../protocol.md) Python 族全量。

## 边界与禁区

- 本卡不验证真实工作区；SliverShield 复验属 GJ-16B 重跑。
- 若枚举过程中发现某类凭据文件**按名不可判**（如无扩展名的私钥），按 L3 记录为设计缺口，不在本卡扩大范围。
