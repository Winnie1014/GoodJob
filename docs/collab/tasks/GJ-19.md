## 背景

信道 [#73 七](../channel.md) 记录：GJ-16B 运行中 `apps/mobile/ios/Flutter/ephemeral/flutter_native_integration.env` 通过了 `WorkspaceScanner._is_sensitive`，进入 `source_artifacts` 与 `source_revisions` 并产生 1 条 Evidence。该文件为 Flutter 生成的构建配置，无凭据，且经核未进入任一 HTML 产物，**不构成泄漏事故**——但闸门本身有覆盖缺口。

**出卡侧更正（本卡为准，覆盖 #71 四与 #73 七的表述）**：`_is_sensitive` 的判定**已有四种形态**——精确名（`== ".env"`）、前缀（`.startswith(".env.")`）、固定名字集合（`in {...}`）、后缀（`.endswith((".key", ".p12", ".pem", ".pfx"))`）。缺陷**不是"缺少后缀机制"**，而是 `.env` 未纳入后缀集合，导致 `production.env`、`local.env`、`secrets.env` 等常见命名漏判。

**两个消费方向**（出卡前实测，非推断）：`scanner.py:1579` 的工作树索引过滤，与 `scanner.py:236` 的 `_safe_history_path`（供 `history.py` 与 `git_metadata.py` 过滤 Git 历史路径）。本卡的修复对两者同时生效，这是修改纯函数的必然结果，**不是本卡新增的耦合**。

## 目标

`*.env` 后缀形不再漏判，且该函数的判定行为被一份**独立于生产实现**的基线锚住——使任何成员删除、规则放宽或大小写归一化丢失都会被测试接住。

**本卡不扩大敏感名字集合**，只补 `.env` 一个后缀成员。

## 接口契约

**契约 1 — 唯一功能变更是把 `.env` 纳入既有后缀集合。** `production.env`、`local.env`、`secrets.env` 判为敏感。同时保持 `.env` 自身与 `.env.production` 形态仍判为敏感——注意 `".env".endswith(".env")` 为真，合并既有分支时勿删出覆盖洞。

**契约 2 — 基线 oracle 必须独立于生产实现。** 用于回归的期望集合**不得从 `_is_sensitive` 的生产常量导入、派生或反射获取**，必须是测试侧独立冻结的字面数据。理由：同源 oracle 会与实现一起被改，"零回归"因此可在成员被删的情况下仍然全绿。

**契约 3 — oracle 的覆盖面由三部分构成**，缺一不可：

1. **既有全部成员**：修改前判为 `True` 的每一个名字，逐个列入，不抽样；
2. **各规则的代表值**：精确名、前缀、名字集合、后缀四类各至少一个正例，且**大小写变体**（如 `ID_RSA`、`Secrets.JSON`）——现码先 `lower()` 再匹配，删掉归一化而 oracle 只有小写时会静默全绿；
3. **区分性阴性样本**：形近但不应判敏感的名字，须**能使过宽实现变红**。至少覆盖 `secretary.md`（防 `startswith("secret")` 式放宽）、`.envoy`、`environment.md`、`env.example`、`README.env.md`。若认为其中某个应判敏感，按 L2 上报，不擅自改判据。

**契约 4 — 无新增运行时依赖。** Python 侧 `dependencies = []` 是既定供应链边界，新增依赖属红区，需 L1。

## DoD

**D1｜后缀覆盖。** `_is_sensitive("production.env")`、`("local.env")`、`("secrets.env")` 均为 `True`，各有独立断言。

**D2｜oracle 零回归。** 修改前判为 `True` 的每个名字修改后仍为 `True`；契约 3 的三部分全部通过。

**D3｜变异门槛（防假绿），三项均须使测试变红：**

1. 从后缀集合移除 `.env`；
2. 从名字集合中移除**任意一个**既有成员（交付报告点名所选成员）；
3. 移除 `lower()` 大小写归一化。
