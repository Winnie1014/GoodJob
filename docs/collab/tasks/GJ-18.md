## 背景

信道 [#69](../channel.md) 报告 SliverShield 的 `apps/mobile/ios/Flutter/ephemeral/...` 被建成正式模块。[#73](../channel.md) 裁决驳回了"缺少 Flutter 硬排除"的根因诊断：该目录已被 `apps/mobile/ios/.gitignore` 的 `Flutter/ephemeral/` 忽略，`git check-ignore -v` 可独立复核。

真因是 `runtime/src/goodjob/scanner.py` 的 `IgnoreMatcher.matches()` 缺少「多段路径模式匹配路径前缀」规则。现有三条匹配规则为：整串 `fnmatch`、单段匹配（**仅当模式不含 `/`**）、目录祖先单段匹配。三条都无法使 `a/b/` 命中 `a/b/c/d`——**多段目录模式只匹配目录自身，不匹配其任何后代**。

`_iter_project_files` 先收集全部候选文件、再逐文件过 `matcher.matches()`，**无目录剪枝**，因此该缺陷没有任何兜底。

该缺陷同时是**静默**的：`_unsupported_issue` 覆盖前导 `/`、`**`、`/` 与通配符共存三类，独漏纯多段目录模式——既不生效，也不产生任何 ScanIssue。这违反 GJ-05 在 [anti-patterns.md](../anti-patterns.md) 确立的「近似必须可见」。

## 目标

1. 多段路径模式按 Git 语义匹配其后代，不再只匹配目录自身；
2. `IgnoreMatcher` 与 Git 之间**剩余的**每一处语义差异都产生可见 ScanIssue，不存在"既不生效也不披露"的模式类别。

不追求与 Git 完全等价——本类保持"确定性子集"定位（见其 docstring）。**追求的是子集边界可见。**

## 接口契约

**契约 1 — 语义枚举以上游为事实源。** 语义差异清单**以 `gitignore(5)` 的 PATTERN FORMAT 一节为唯一事实源**（`git help gitignore`，或 `https://git-scm.com/docs/gitignore` 同节），逐条对照当前实现。**不得凭印象手写清单**——本卡不内联该清单正是为此（[architect.md §1.3 门禁 9](../architect.md)）。交付报告须列出所依据的 Git 版本。

**契约 2 — 每条语义有明确归宿。** 对照结果为一张决策表，每行三列：Git 语义 / 当前实现行为 / 处置（`支持` 或 `披露`）。**不允许出现第三种处置**。判为 `披露` 的，必须有对应 `ignore_pattern_unsupported` ScanIssue 且 `raw_pattern` 字段带原始行。

**契约 3 — 多段路径模式处置为 `支持`。** 含内部 `/` 的模式锚定到该 `.gitignore` 所在目录，并匹配其后代。这是本卡的核心修复项，不得降级为"披露"。

**契约 4 — 既有生效行为零变更。** 当前已能正确命中的模式形态，修复后行为逐条不变。`ScanIssueDraft` 与 `IgnorePatternIssueDraft` 的字段与 `kind` 取值不变；`excluded` Counter 的键名不变。

**契约 5 — 无新增运行时依赖。** Python 侧 `dependencies = []` 是既定供应链边界，新增依赖属红区，需 L1。

## DoD

**D1｜多段模式后代匹配。** `IgnoreMatcher` 以 `(base=".", pattern="build/outputs", include=False, directory_only=True)` 构造时，`matches("build/outputs/apk/app.apk")` 为 `True`；嵌套形态 `(base="apps/mobile/ios", pattern="Flutter/ephemeral", …)` 对 `apps/mobile/ios/Flutter/ephemeral/Packages/x/Package.swift` 为 `True`。两者均有独立用例。

**D2｜变异断言（防假绿）。** 删除本卡新增的前缀匹配规则后，D1 的用例必须变红。交付报告贴出变异前后的失败用例名集合。

**D3｜阴性对照。** 多段模式不得过度匹配：`(base=".", pattern="build/outputs")` 对 `build/outputsX/a.txt` 与 `other/build/outputs/a.txt` 均为 `False`（后者验证锚定语义）。

**D4｜披露完备。** 构造一个属于决策表中每个 `披露` 行的模式，断言各自产生 `ignore_pattern_unsupported` ScanIssue。**再断言：决策表中判为 `支持` 的模式不产生该 issue**（防止把披露当万能出口）。

**D5｜本仓自扫描实证。** 对 GoodJob 仓库自身执行一次扫描（临时 data directory，位于仓库外）。`prototypes/dashboard/node_modules/` 与 `prototypes/dashboard/out/` 下的文件在修复前进入索引、修复后计入 `excluded["gitignore"]`。**数量以命令计算，不写字面量**：基线数取 `find prototypes/dashboard/node_modules prototypes/dashboard/out -type f 2>/dev/null | wc -l`，断言修复后该目录下进入 `source_artifacts` 的条数为 0。

**D6｜既有回归零变更。** `runtime/tests/test_scanner.py` 既有用例全绿，且**不修改任何既有用例的断言**；确需修改的按 L2 上报并说明。

**D7｜门禁全绿。** [protocol §8](../protocol.md) Python 族全量：`ruff format --check`、`ruff check`、`mypy`、`pytest -q`。
