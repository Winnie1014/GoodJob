## 1. 呈现目标与非目标

看板服务一个具体场景：Owner 在面试前的有限时间内回答三个问题——我要讲什么、凭什么这么讲、哪里不能讲。呈现层因此按“可判定性优先于观感”设计，三条原则：

1. **限制先于叙事**：覆盖缺口、时效降级和归因不足必须出现在任何漂亮结论之前，而不是折叠在角落（`FR-15`、`NFR-05`）。
2. **两步内到证据**：任一关键 Claim 到完整证据指针不超过两次交互（`FR-11`）。
3. **只读要显形**：看板不写状态，但必须给出更新状态的明确出口，而不是提供无效控件（`FR-14`）。

呈现层非目标，首版明确不做：营销式 hero 区、自定义显示字体或图标字体、编排动效、饼图/环形进度/雷达图/双轴图、无限滚动、列表虚拟化、可切换主题皮肤系统、任何形式的用户偏好持久化。

### 1.1 呈现基调

看板的形态取自它自己的领域：这是一份**带保管链的取证卷宗**，不是运营仪表盘。每条断言都附路径、内容哈希、提交状态与时效，产品的立场是明确说出能证明和不能证明什么。呈现基调因此定为「校勘本 / 卷宗」而不是「dashboard」：

- **不使用卡片网格**。用留白、细分割线和悬挂式版式建立层级；界面里没有一块「面板」。
- **首屏论点就是边界**。覆盖条位于报头正下方，先讲清工作区里有多少项目参与评分、多少沿用旧快照、多少无基线，再进入任何叙事。这取代了「大数字 + 辅助指标」式的模板 hero。
- **出处悬挂在版心左侧**。断言在版心，项目/模块作用域与证据类型悬挂在左栏；左栏的存在本身编码了「一切都能回溯」。
- **墨色浓度是第二条置信通道**。`current` 用主墨色与实线悬挂规则；`stale` 用次墨色与点线；`plan` 用虚线；`missing` 用告警色规则。它只是图标 + 文字的**加强**，不单独承载语义。

## 2. 视图与深链

看板是单入口文档内的若干视图，切换只改 `location.hash`，不发起任何导航或请求。

| ID | 视图 | 职责 | 深链形式 |
| --- | --- | --- | --- |
| `DASH-V01` | 总览 | 降级注解、岗位镜头维度权重、项目排序与分数复算 | `#/v1/overview` |
| `DASH-V02` | 项目与模块 | 项目/模块树导航、项目章节、模块内 Claim 列表 | `#/v1/project/<project_id>[/module/<module_id>]` |
| `DASH-V03` | 证据横切 | 跨项目检索与筛选 Claim/Evidence，按维度、时效、support、facet 收敛 | `#/v1/evidence?…` |
| `DASH-V04` | 知识缺口 | 按作用域和严重度列出 `KnowledgeGap`、候选追问、影响的叙事 | `#/v1/gaps` |
| `DASH-V05` | 面试与复习 | 分层题库、追问路径、薄弱点、冻结的掌握度与 `next_review_at` | `#/v1/interview[/target/<review_target_id>]` |

深链片段以 `v1` 起始，与 `ReportBundle` 契约主版本一致。跨版本快照之间互相粘贴深链时，路由必须明确报“该链接属于其他契约版本”，不得静默落到错误对象。深链只在同一快照内有意义；看板不尝试跨快照解析。

## 3. 总览首屏的固定顺序

首屏顺序是本契约的核心约束，不允许为观感调换。

| 层 | 内容 | 依据 | 不允许 |
| --- | --- | --- | --- |
| `L0` | 取证条（常驻）：`completed`/`partial` 徽章、`preparation_run_id` 短形式、`bundle_sha256` 前缀、生成时间、主语言、“已冻结·只读” | 快照不可变且会被同时打开多份，必须一眼区分 | 不显示为可编辑字段；不隐藏 `partial` |
| `L1` | 报头（常驻）：岗位名、职级及其来源（Owner 覆盖或推断）、JD 来源或“无 JD 假设” | `FR-01`、`FR-02`、`FR-05` | 不省略 JD 缺失或职级推断的事实 |
| `L2` | 覆盖条（常驻）：按项目的 `snapshot_disposition` 比例分段，并给出「共 N 个项目里有 M 个参与评分」与逐段计数。已评分实心、沿用旧快照斜纹、无基线仅描边、已排除留白 | `artifacts-and-learning.md` §8、`FR-15` | 不折叠；不把 `carried_forward` 归入「未评分」——它同样参与评分 |
| `L3` | 降级注解：逐条列出 `carried_forward`/`failed_no_baseline`/`excluded` 项目、`ScanIssue` 严重度、stale/missing 证据数、缺角色或学习上下文的项目，每条附影响与补救动作，并可跳到对应筛选结果 | `artifacts-and-learning.md` §8、`FR-15` | 不折叠、不合并成单个“存在部分缺口”提示、不放到叙事之后 |
| `L4` | 岗位镜头维度权重条，随后是项目排序：`rank`、项目名、`snapshot_disposition`、`final_score_milli`，并展示 `base_score_milli × coverage_bps → final_score_milli` 的复算行；不合资格项目单列在分隔线下且标“仅进入覆盖，不评分” | `FR-08`、`FR-09`、`EVID-INV-22` | 不隐藏低分合资格项目；不给不合资格项目编造分数或名次 |

`L0` 与 `L2` 是全局构件，出现在每个视图上方，因此离开总览后覆盖情况不会消失。`L3` 只出现在总览。

`partial` 快照的 `L3` 必须非空。`completed` 快照若 `L3` 为空，显示一行明确的“本次未记录覆盖限制”，而不是省略整层——空白不能与“没有问题”混淆。

## 4. 状态视觉编码

有五组互相正交的状态，而保留状态色只有四个。编码规则：状态色只发给“影响可信度的降级”，其余状态走非颜色通道。

| 状态组 | 取值 | 通道 |
| --- | --- | --- |
| Evidence 时效 | `current`、`stale`、`missing`、`plan` | 状态色 + 图标 + 文字标签 |
| 项目 disposition | `fresh`、`carried_forward`、`failed_no_baseline`、`excluded` | 状态色 + 图标 + 文字标签 |
| `support_level` | `single_source`、`cross_checked`、`user_confirmed`、`conflicted` | 点阵强度 + 文字；仅 `conflicted` 借用 critical 色并强制展示反证 |
| `commit_state` | `committed`、`modified`、`untracked`、`historical`、`not_applicable` | 等宽单色标签，不分配颜色 |
| `continuity_status` | `new`、`continued`、`reassess_required` | 边框样式（实线/无框/虚线）+ 文字，仅出现在 `DASH-V05` |

硬规则：

- 任何状态都不得只靠颜色表达，必须同时具备图标与文字（`forced-colors`、打印和色觉差异下仍可辨）。
- 状态色不得被复用为数据系列色，数据系列色也不得用于状态。
- 浅色与深色两套取值各自独立选取，跟随 `prefers-color-scheme`。首版不提供主题开关：`file://` 的 origin 不稳定，`localStorage` 不可靠，而看板不应持有任何用户状态。

## 5. Claim 到 Evidence 的展开

这是看板的核心组件，`DASH-V02`/`DASH-V03`/`DASH-V05` 共用同一实现。

Claim 卡片必需：statement、`facets` 集合、`support_level`、所属项目/模块作用域、叙事类型（能力/学习/客观实现/个人归因）。

每条 Evidence 行必需：项目、worktree 或分支（仅在存在分支差异时）、模块（如适用）、`evidence_kind`、相对路径与 locator、内容哈希或 commit locator、`commit_state`、时效、`supported_facets`、`relation`。

- 内容等价的来源可折叠，但必须能展开全部 worktree 来源；折叠态需显示被折叠的来源数量（`artifacts-and-learning.md` §3.1）。
- `stale`、`missing`、`plan` 证据必须随行显示降级措辞（“只作历史限制”“已规划/已文档化”），不得与 `current` 证据同等呈现。
- `support_level=conflicted` 必须在同一视野内并列展示 `contradicts` 证据，不允许只把强度调低。
- 展开不复制源码正文或 diff；只呈现指针、哈希与短概述（`ADR-0003`、`EVID-INV-01`）。

## 6. 图表形式与数值呈现

| 数据 | 形式 | 理由 |
| --- | --- | --- |
| RoleLens 维度权重 | 横向条形 + 直接标签 | 维度名较长且需精确比较；雷达图面积失真、不可比 |
| 项目 `final_score_milli` | 横向条形，按 `rank` 排序 | 幅度比较 |
| `coverage_bps` | 单条 meter | 单一比例，不用环形或饼图 |
| `base × coverage → final` | 等宽复算行文本 | 让“分低是因为覆盖度低”而非“项目差”可见 |
| 掌握度分布 | 分段计数条 | 三到四个有序档位的计数 |
| 工作区覆盖构成 | 按项目比例分段的单条覆盖带 + 逐段计数 | 一眼看出「多少参与评分、多少沿用旧快照、多少不评分」；已排除段留白，不给它视觉重量 |

数值呈现规则：

- `weight_bps`、`coverage_bps` 以两位小数百分比显示（`2600` → `26.00%`），并可在同一处显示原始 bps，便于与 manifest 对账。
- `*_milli` 保持 0..1000 整数显示，不换算为百分比，避免与 bps 混淆。
- 所有比较与排序读取整数原值，绝不用浮点重算；呈现层不做任何四舍五入以外的算术。
- `font-variant-numeric: tabular-nums` 只用于需要纵向对齐的列（排名、分数列、轴刻度），不用于正文。

## 7. 排版与布局

### 7.1 三个排版角色

不加载任何字体文件（`ADR-0008` 决策 1），所以性格来自角色分工与字号级差，而不是字体资源：

| 角色 | 字族 | 用途 |
| --- | --- | --- |
| 显示 | 系统衬线（`ui-serif` → 中文宋体 → Georgia） | 只用于报头岗位名、章节标题和排名序号。中文宋体是公文与书籍的字面，与「卷宗」基调一致 |
| 正文 | 系统无衬线（`system-ui` → 苹方 / 微软雅黑） | 断言、说明、注解。中文行高不低于 1.8 |
| 数据 | 系统等宽（`ui-monospace`） | 路径、locator、哈希、bps、分数。这是承重角色：哈希与路径必须能逐字符肉眼核对，不是装饰 |

字号级差固定为 12 / 12.5 / 13.5 / 14.5 / 16 / 17.5 / 19 / 27 / 44 px，不允许在实现中临时插值。字重只用 400 与 500。`tabular-nums` 只给需要纵向对齐的数字列。

### 7.2 断点

| 断点 | 布局 |
| --- | --- |
| ≥1024px | 两栏：安静的左导航约 12rem + 版心；版心内部再分出约 8.5rem 的出处悬挂栏。整页居中，最大宽度约 1120px |
| 768–1023px | 同为两栏，导航与悬挂栏收窄 |
| <768px | 单栏：导航收为顶部选择器，悬挂栏归零，出处转为行内块 |

- 正文可读宽度上限约 43rem（约 68 个中文字符）；路径、locator 与哈希允许任意位置换行。
- 不设常驻右栏。首版没有值得占据一整栏的只读内容；快捷键提示放页脚，快照身份放顶部取证条。
- 任何宽度下不得出现横向滚动或横向遮挡。窄屏的多列结构必须改为纵向块，而不是套一个横向滚动容器（`artifacts-and-learning.md` §6）。
- 不使用嵌套滚动容器；页面只有一个主滚动轴。
- `@media print` 必须展开全部折叠区、打印完整 locator 与哈希、隐藏导航与交互控件，并保留 `L0` 取证条、`L1` 报头与 `L2` 覆盖条。

## 8. 交互

全部交互在本地完成，不发起网络请求，不写入任何持久状态。

- **检索**：使用 `ReportBundle` 内预建的倒排索引做子串匹配。不把用户输入编译为正则表达式。
- **筛选**：维度、项目、模块、`snapshot_disposition`、Evidence 时效、`commit_state`、`support_level`、`facets`、缺口严重度、`continuity_status`。筛选条件反映到 hash，可自行回到同一视图状态。
- **展开**：Claim 展开证据、Evidence 展开等价来源、缺口展开候选追问、题目展开追问路径。
- **复制**：locator 与 Skill 调用本身就是复制控件（点击即复制，`aria-label` 说明目标），不另设按钮。剪贴板不可用时降级提示「请手动选中」，不报错。
- **键盘**：`/` 聚焦检索、`j`/`k` 在当前列表移动、`Enter` 打开、`e` 展开证据、`Esc` 回到检索。快捷键常驻页脚，因此不设「显示快捷键」的独立绑定或浮层。全部交互必须在无鼠标条件下可达，焦点顺序与视觉顺序一致，焦点环可见。

## 9. 呈现层安全实现规则

本节把 `NFR-08`、`ARCH-INV-11` 落成呈现层可检查的实现规则，技术选择理由见 [ADR-0008](../30-decisions/adrs/ADR-0008-single-file-dashboard-and-structured-token-embedding.md)。

1. **零 Markdown 解析器**。看板只接收 `ReportBundle` 的结构化 inline token（见[证据模型](evidence-model.md) §3 `ReportInlineToken`），不接收 Markdown 或 HTML 字符串。前端把 token 映射为文本节点与已知安全元素。因此“净化原始 HTML、事件属性、`javascript:` URL”这一类问题在结构上不存在，而不是靠净化函数兜住。
2. **嵌入转义**。报告数据以 canonical JSON 嵌入入口文档；序列化时必须把 `<`、`>`、`&`、`=`、U+2028、U+2029 转为 `\uXXXX` 转义序列。`bundle_sha256` 始终计算在 canonical JSON 上，嵌入层转义不参与哈希，因此产物哈希仍可独立复算。
3. **CSP**。入口文档必须携带 `<meta http-equiv="Content-Security-Policy">`，至少包含 `default-src 'none'`、按哈希允许的 `script-src`、按哈希允许的 `style-src`、`img-src 'none'`、`font-src 'none'`、`connect-src 'none'`、`object-src 'none'`、`frame-src 'none'`、`form-action 'none'`、`base-uri 'none'`。不使用 `unsafe-inline`、`unsafe-eval` 或任何远端来源。
4. **禁用的 API**。不使用 `eval`、`new Function`、`setTimeout`/`setInterval` 的字符串形式、`innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`、`srcdoc`，也不通过属性字符串注册事件处理器。样式方面禁用全部运行时写入：`setAttribute("style", …)`、`cssText` 与 `element.style` 的任何属性赋值。`style-src` 的哈希白名单只覆盖内联 `<style>` 元素、不覆盖 `style` 属性，后者会被 CSP 静默拦下；CSSOM 虽不受 CSP 约束，但一条不作区分的禁令更容易静态机检。动态几何一律用内联 SVG 的几何属性（`x`/`width`/`height`）配合整数 `viewBox` 表达，比例保持整数原值（见 `DASH-INV-05`）。构建门禁必须能静态检出以上全部调用。
5. **URL 与路径**。来自不可信数据的 URL（JD、用户回答、文档内容）一律不渲染为可点击链接，只作为可选中文本并标注“外部链接（未激活）”。locator 与相对路径绝不渲染为 `file://` 链接或任何可导航目标。
6. **图标与字体**。图标使用内联 SVG 元素，不使用图标字体、不使用 `<img>`。字体只使用系统字体栈，不加载任何字体文件。
7. **门禁的判定层级**。以上规则的自动检查必须在结构层判定，不得把入口文档扁平化成一个字符串后用模式匹配代替。属性检查只作用于产物结构，`<script id="report-data" type="application/json">` 的数据区不参与——数据区已按规则 2 转义，其中的任何内容都不可能成为标记或属性。门禁必须在任意真实工作区内容下成立：渲染发生在 `ReportBundle` 冻结之后，一次由用户内容触发的渲染拒绝会让该运行确定性地不可发布，重试同一 bundle 必然同样失败。
8. **行为断言不得退化为源码文本断言**。前端静态门禁可以检查禁用 API 与禁止的资源引用，但不得用「源码中必须出现某段字符串/某句 UI 文案」来代替对渲染结果的断言。呈现行为由 `DASH-01` 至 `DASH-12` 在真实文档上核对（见 §12）。

## 10. 只读约束的出口

看板不写复习状态。呈现层因此不得出现“标记已掌握”“保存”“提交”一类控件——那会把只读约束伪装成可写。

替代做法：复习区显示该状态冻结于哪个快照与时间，并提供一段可复制的 Skill 调用文本，说明状态更新经 Skill/Python 落库后，需 Owner 显式创建新的 `PreparationRun` 才会出现在下一份看板中。该文本是纯文本，不可点击执行（`FR-14`、`NFR-06`）。

| `DASH-INV-03` | 任一关键 Claim 到完整证据指针不超过两次交互；折叠的等价来源必须可展开为全部 worktree 来源。 |
| `DASH-INV-04` | 任何状态都不得只靠颜色表达；状态色与数据系列色不得互相冒用。 |
| `DASH-INV-05` | 呈现层不做浮点算术；`weight_bps`/`*_milli`/`coverage_bps` 按整数原值比较排序，只在显示时格式化。 |
| `DASH-INV-06` | 看板不含 Markdown 或 HTML 解析器；所有富文本来自结构化 token。 |
| `DASH-INV-07` | 不可信数据不得成为可点击链接或可导航目标；locator 只作文本呈现。 |
| `DASH-INV-08` | 入口文档在断网且无本地服务时双击可完整使用；发现任何远端依赖或 CSP 违规时该运行不得发布为成功快照。 |
| `DASH-INV-09` | 看板不提供写状态控件；只读约束通过可复制的 Skill 调用给出出口。 |
| `DASH-INV-10` | Markdown 与 HTML 对同一 Claim 呈现相同的证据状态、facet、`commit_state` 与限制；呈现层不得引入 Markdown 未表达的结论。 |
| `DASH-INV-11` | 呈现层与产物门禁在结构层判定，不在扁平字符串上判定；门禁在任意真实工作区内容下成立，不得出现由用户内容触发的确定性渲染拒绝。行为由真实文档核对，不由源码文本匹配代替。 |

## 12. 可判定验收规则

| ID | 可判定输入 | 必须输出 | 失败或降级行为 | 需求映射 |
| --- | --- | --- | --- | --- |
| `DASH-01` | 断网、无本地服务，双击入口文档并打开开发者工具网络面板 | 视图、检索、筛选、证据展开、缺口与复习状态全部可用，网络面板零请求 | 出现任何请求即视为渲染失败，不发布快照 | `FR-12`、`NFR-03` |
| `DASH-02` | 在 Chromium 与 WebKit 各完整浏览全部视图并执行全部交互；同一核对注入一次 `style` 属性作为阳性对照 | 两个引擎干净加载后控制台零 CSP 违规、零脚本错误；阳性对照必须触发违规 | 任一引擎出现违规则该运行不发布为成功快照；阳性对照不触发说明 CSP 未生效，本项及依赖它的结论一并作废 | `NFR-03`、`NFR-08` |
| `DASH-03` | 字段含 `</script>`、`<img onerror=…>`、`javascript:` URL、事件属性、`style="…"` 片段、U+2028/U+2029、RTL 覆盖字符、超长无空格串 | 全部以可读文本呈现，长串按字符换行不撑破布局；含 `style=` 的 `code` token 不影响渲染成功 | 不执行脚本、不发请求、不产生可点击外部链接；不得因语料内容拒绝渲染 | `NFR-08`、`ART-12`、`DASH-INV-11` |
| `DASH-04` | 375px 宽视口浏览全部视图 | 无横向滚动、无遮挡，多列表格已转为定义列表 | 出现横向滚动容器即不通过 | `FR-12`、`NFR-03` |
| `DASH-05` | `partial` 快照，含 `carried_forward`、`failed_no_baseline`、`excluded`、stale 证据与缺上下文项目 | `L0` 标 `partial`，`L2` 覆盖条分段与计数正确（`carried_forward` 计入参与评分），`L3` 逐条列出原因、影响与补救动作并可跳到对应筛选 | 不得折叠、合并或下移；不得把 `carried_forward` 算作未评分 | `FR-15`、`NFR-05` |
| `DASH-06` | 任一关键 Claim，含 current/stale/missing/plan 混合证据与内容等价的多 worktree 来源 | 两次交互内看到全部必需证据字段；等价来源可展开为全部 worktree | stale/missing/plan 随行显示降级措辞；不复制源码或 diff | `FR-11`、`NFR-02` |
| `DASH-07` | 打印或导出为 PDF | 折叠全部展开、locator 与哈希完整、保留快照身份与降级带、隐藏交互控件 | 交互控件或截断的 locator 出现在打印结果即不通过 | `FR-12` |
| `DASH-08` | 仅用键盘完成：切换视图 → 检索 → 施加筛选 → 展开证据 → 复制 locator | 全流程可达，焦点顺序与视觉顺序一致且焦点环可见 | 存在只能鼠标触达的交互即不通过 | `FR-12`、`NFR-03` |
| `DASH-09` | 启用 `forced-colors`、灰度打印与色觉模拟 | 五组状态仍可区分（图标 + 文字），分数与覆盖度仍可读 | 任一状态退化为纯色区分即不通过 | `NFR-03` |
| `DASH-10` | 同时打开同一岗位的两份快照（一份 `completed`、一份 `partial`），并粘贴另一契约版本的深链 | 身份条可区分两份快照；跨版本深链明确报错 | 深链不得静默落到错误对象 | `FR-12`、`NFR-04` |
| `DASH-11` | 复习区含 `new`/`continued`/`reassess_required` 三种目标 | 三态可区分，显示冻结时间与可复制 Skill 调用 | 不出现任何写状态控件；不创建提醒 | `FR-14`、`NFR-06` |
| `DASH-12` | 同一冻结快照的 Markdown 与 HTML 逐条比对关键 Claim | 证据状态、facet、`commit_state` 与限制完全一致 | 任一不一致视为同源约束破坏，不发布快照 | `FR-12`、`NFR-04` |

## 14. 非首版边界

首版不做：常驻服务或需要 HTTP 的交互式 Dashboard（`F-006`）、跨快照对比视图、跨岗位并排比较（`F-001`）、在看板内直接编辑简历或写入复习状态、图表下钻到源码正文、用户偏好或主题持久化、看板内英文切换（英文只作独立派生导出，不生成英文 HTML，见 `FR-13`）。
