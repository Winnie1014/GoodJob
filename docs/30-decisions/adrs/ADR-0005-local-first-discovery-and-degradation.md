# ADR-0005：本地优先发现与可见的部分降级

> 状态：已接受  
> 日期：2026-07-24  
> 权威范围：项目发现、敏感排除、嵌套仓库和扫描失败行为  
> 上游：[产品目标](../../00-product/vision-and-goals.md)  
> 下游：[扫描设计](../../20-architecture/scanning-and-analysis.md)、[验收基线](../../40-delivery/acceptance-baseline.md)

> 首版范围收窄：决策 4 中“配置可设置少量精确安全例外”的机制推迟为 `F-009`，首版配置只承载项目级排除规则（`D-034`、[扫描设计 §4.3](../../20-architecture/scanning-and-analysis.md)）。这是范围推迟而不是改判——该机制是唯一会让扫描读到本来被排除内容的入口，恢复它需要先完成 `F-009` 定义的秘密拒绝校验、例外命中审计与覆盖呈现设计。决策 4 的其余部分与全部其他决策不变。

## 背景

真实工作区包含 linked worktree、嵌套仓库、未提交文件、非 Git 项目、大型依赖目录和敏感本地配置。全有或全无的扫描会因一个损坏目录阻断全部结果，静默跳过又会制造虚假的完整性。

## 决策

1. 只扫描用户显式提供且本机可读、并已按 ADR-0006 取得本会话授权回执的工作区内容；`.git` 指向根外时的精确授权、双向绑定和字段限制由 [ADR-0006](ADR-0006-authorized-codex-analysis-and-external-git-metadata.md) 收紧定义。
2. 在应用父仓库 ignore 前先发现嵌套 Git 根；每个独立仓库应用自己的 ignore。
3. Git worktree 使用 common-dir 归并项目身份，同时保存各工作树来源和当前状态。
4. 硬排环境变量、密钥、依赖、构建、缓存和运行时数据；配置只能对普通 ignore 或结构性排除设置少量精确安全例外，不能重新纳入实际秘密。
5. 纳入未忽略的已提交、已修改和未跟踪代码/文档，并明确标记来源。
6. 权限不足、仓库损坏和语言不支持均产生结构化 ScanIssue；其余项目继续生成结果。
7. 准备包必须展示覆盖范围、跳过原因和补救动作，不得静默声明完整。

## 影响

- 大工作区可获得部分但诚实的结果。
- 嵌套项目不会因父仓库 ignore 消失。
- 用户可以区分当前实现、未提交进展与文档计划。

## 否决方案

- 只读 Git 跟踪文件：会漏掉正在进行中的学习材料。
- 尽量读取所有文件：会扫描大量构建物并增加密钥暴露风险。
- 任一失败终止全部任务：降低跨项目工具的可用性。
- 静默跳过：用户无法判断准备材料是否遗漏关键经历。

## 验证

- 父仓库忽略内层仓库时，内层仍作为独立项目出现。
- node_modules、build、缓存和敏感配置不进入证据库。
- 人工制造一个不可读项目后，其余项目仍生成材料，且缺口清单可见。
