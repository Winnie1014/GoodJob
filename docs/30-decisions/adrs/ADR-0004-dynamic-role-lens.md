# ADR-0004：由模型生成动态 RoleLens

> 状态：已接受  
> 日期：2026-07-24  
> 权威范围：岗位输入、JD、职级和岗位分析镜头  
> 上游：[产品需求](../../10-product/product-requirements.md)  
> 下游：[系统设计](../../20-architecture/system-design.md)、[产物设计](../../20-architecture/artifacts-and-learning.md)

## 背景

应用软件、中间件、架构、系统、测试和底层软件岗位关注的证据不同。固定模板无法覆盖未来岗位，但完全无框架的自由生成又会导致同一岗位跨运行漂移。

## 决策

1. 每次 PreparationRun 只指定一个主岗位，可附 JD 文本或本地文件。
2. 模型根据岗位名、JD、通用岗位参考和项目证据生成本次 RoleLens。
3. RoleLens 至少记录岗位名称、职级、分析维度与权重、必需证据类别、项目排序规则、输出章节、面试问题策略、知识缺口规则和显式假设。
4. JD 优先用于判断职级，用户显式职级覆盖自动推断。
5. 无 JD 时允许从岗位名生成候选 RoleLens，但必须在产物中展示关键假设。
6. 内置岗位材料只作为思考框架，不是固定枚举或必须照搬的内容。
7. RoleLens 随准备快照持久化，确保同一次输出可重现。

## 影响

- Skill 能处理未预见岗位，而无需先发布新版本。
- 同一证据图谱可为不同岗位重排，不重复扫描。
- 模型生成结果必须持久化并展示假设，避免隐式漂移。

## 否决方案

- 固定岗位模板：输出稳定但无法支持测试、底软等新岗位。
- 完全依赖 JD、无 JD 就失败：阻断用户只有岗位名称的常见场景。
- 一次并排多个主岗位：首版输出失焦；保留为未来扩展。

## 验证

- 相同项目在应用软件与系统工程岗位下产生不同证据排序和问题策略。
- 输入未内置的岗位名称时仍可生成完整且带假设的 RoleLens。
- 提供 JD 和职级覆盖后，产物引用覆盖后的职级。
